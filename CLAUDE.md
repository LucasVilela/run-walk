# Run-Walk (working name) — 9-week beginner run/walk app

Native iPhone app: run/walk intervals → 30 minutes non-stop in 9 weeks.
Never use the trademark "Couch to 5K"; say "a 9-week beginner run/walk plan".

## Stack (locked)
- SwiftUI, Swift 6 strict concurrency, iOS 26 minimum, iPhone only.
- Project generated by xcodegen from `project.yml`; run `xcodegen generate` after adding files.
- Pure logic lives in the local package `RunKit` (no UIKit/SwiftUI imports). App target holds views,
  `@Observable` stores and thin services.
- Storage: system SQLite3 with a small typed wrapper and numbered migrations (`RunKit/Sources/RunKit/DB`).
- Audio: AVSpeechSynthesizer + bundled beeps; AVAudioSession `.playback`, `.mixWithOthers`, `.duckOthers`.
- Haptics: Core Haptics. No GPS or location at all (removed by request, 2026-11-09): runs are time-only;
  distance is an optional number typed on the summary. Locked-phone cues = scheduled notifications.
- Charts: Swift Charts; segment bar is a SwiftUI shape. Notifications: local only.
- Tests: Swift Testing (`cd RunKit && swift test`, then `./scripts/test.sh`). Format: `swift format`.
- No third-party dependencies without asking first.

## Product principles
1. One obvious next step: Today always shows the next run and one big Start button.
2. Eyes-free: every transition = voice + beeps + vibration.
3. Never punish: missed runs slide forward, repeats are normal, no streaks, no red "missed".
4. Offline and private: no account, no network requests, all data on device.
5. Calm and simple: 4 tabs max, big type, few numbers, plain words.

## Coding rules
- Run engine is a pure state machine with an injected clock. Never sum ticks:
  elapsed = now − startedAt − pausedTotal. UI redraws every ~250 ms.
- Engine emits events; CuePlayer performs them. Don't replay missed cues after background:
  announce the current segment once.
- Program data in `RunKit/.../Plan/Program.swift` is exact; do not change it.
- Coach rules, scheduler, day-by-day and calculations are deterministic and unit-tested.
- Never log personal data.
- Keep files small. No extra screens, backends, analytics, ads or "nice-to-haves".
- Looks (Settings → Look): `App/Looks.swift` defines Calm (default, the brief's palette), Futuristic,
  Bold, Optimized, Sunrise. Every token in `Theme` follows the current look; never hard-code fonts,
  colours or corners. `LookTests` enforce text contrast for every look.
- Calm colours from `Theme.swift`: run #FF6B4A, walk #2BB3A3, warm-up/cool-down #6B7A90,
  bg #FAFAF7 / #111315, text #1A1C1E / #F2F2F0. Always show the word, not color alone.
- Type: system font, monospaced digits. Countdown 96, titles 28, body 17, min 15. Dynamic Type on.
- Touch targets ≥ 48 pt; run controls ≥ 72 pt. VoiceOver label on every control.
- Copy: second person, short, warm, no shaming, few exclamation marks.

## Workflow
- Build in the 6 phases in PLAN.md. After each: build, lint, tests, then report
  (✅ done, 🧪 how to test on the phone, ⚠️ open items) and wait for "continue".
- Ask before: new dependencies, deleting files, schema changes after phase 3.
- Same error surviving 3 fix attempts → stop and explain.

## Folders
- `RunKit/Sources/RunKit/{Model,Plan,Engine,Coach,Calc,DB}` + `RunKit/Tests/RunKitTests`
  (Model = UserSettings, RunRecord; weekdays use Calendar numbering, 1 = Sunday)
- Tests that need dates use the fixed Sydney calendar in `CoachTests.swift` (`Cal`).
- Schema v1 is in `DB/Migrations.swift`; all writes go through `RunStore`. App state: `AppModel`
  (`@Observable`, injected clock + calendar), full-screen `Flow` = run → summary.
- `RunWalk/{App,Services,Features,Components,Resources}`; shared views live in Components
  (Styles: `.card()`, `ChoiceChip`, `bottomBar`; RunParts; SettingsControls). Reuse before adding.
- `RunWalkWidgets/` (widget extension: lock-screen widgets + Live Activity) and `Shared/` (compiled into
  both: app-group snapshot + `RunActivityAttributes`). App side: `Services/WidgetBridge.swift`.
- `RunWalkTests/`, `scripts/`. README.md = run/test/build; PHONE.md = on-device steps.
